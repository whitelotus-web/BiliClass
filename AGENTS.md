# BiliClass working agreement

- Keep the teacher's personal library, student responses, model downloads, reports, temporary files, and built executables out of Git. Review the staged file list before each commit.
- Test source changes with the project virtual environment; run the relevant tests and Qt smoke check for UI or classroom changes.
- For work completed on this machine, commit and push code/documentation to the configured private GitHub remote after verification. This reflects the user's standing request from 02/10/2026. Do not force-push or overwrite another collaborator's work; fetch and reconcile first.
- The packaged app is a separate release artifact. Build once after a tested milestone, record the commit/version, and keep model packs and executables out of normal commits.
- Preserve the current Settings tabs (General, Bilingual, Voice, Mascot) unless the user asks to modify them.
